Modern Cryptography

From classical cryptanalysis and the internals of AES, to benchmarking classical and post-quantum primitives in Python's pyca/cryptography.

Cryptanalysis · theory

Breaking Ciphers & the Internals of AES

Built
A theory assessment working through the Vigenère cipher and Kasiski examination, Kerckhoffs's principle, attack models (chosen-plaintext vs chosen-ciphertext), Feistel vs substitution–permutation networks (DES vs AES), block-cipher modes, PKCS#7 padding, and a CBC padding-oracle attack byte-by-byte.
Takeaway
The cipher is rarely the weak point: mode of operation, IV handling, and padding decide whether a construction is actually safe. A padding oracle turns "is this valid?" into full plaintext recovery.
Tools
Kasiski examinationAES (SPN)CBC / CTRPadding oracle
In progress · due Dec 2026
Applied crypto · benchmarking

CryptoBench: Classical vs Post-Quantum

Building
A reproducible benchmark measuring the running times of modern primitives in pyca/cryptography: key establishment (RSA-OAEP, ECDH, X25519, ML-KEM), signatures (RSA-PSS, ECDSA, Ed25519, ML-DSA) and authenticated encryption (AES-GCM, ChaCha20-Poly1305, AES-GCM-SIV), reporting median and IQR across two hardware environments.
Takeaway
Post-quantum KEMs and signatures are already in the standard toolkit; measuring them next to RSA and elliptic-curve schemes makes the real-world cost of the migration concrete rather than theoretical.
Snippet
# Time each run on its own; median + IQR, never the mean
t0 = time.perf_counter_ns()
ct = public_key.encapsulate()          # e.g. ML-KEM-768
elapsed_ns = time.perf_counter_ns() - t0
Tools
Pythonpyca/cryptographyML-KEM / ML-DSA

Penetration Testing

Structured web-application security testing against a deliberately-vulnerable PHP lab, every finding recorded with its request, its vulnerable sink, and the secure-coding control that removes it.

Web app security · defensive

Cross-Site Scripting: 10 Findings, 10 Fixes

Built
Catalogued ten distinct XSS variants against a lab app: reflected, DOM-based (via location.hash), POST-based, HTML-comment and attribute breakouts, JavaScript-context injection, and bypasses of case-sensitive denylists, non-recursive filters and a custom RemoveXSS() sanitiser, documenting the vulnerable sink and correct mitigation for each.
Takeaway
Denylists and custom sanitisers lose; contextual output encoding wins. Every finding resolved to htmlspecialchars with ENT_QUOTES, json_encode for JS context, or a safe DOM sink such as textContent.
Snippet
// Context-correct output encoding beats every blacklist
echo htmlspecialchars($input, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');

// JavaScript context: serialise, don't interpolate
echo "if (" . json_encode($number) . " < 10) { ... }";
Tools
OWASP ZAPXAMPPPHP
Secure coding

From Finding to Fix

Built
Paired every XSS finding with a remediation aimed at the bug class, not the single instance: contextual encoding for output, filter_input() validation for integers, and an established parser (HTMLPurifier) where raw markup genuinely has to be allowed.
Takeaway
Most web risk is trust placed in the wrong place: the client, the filename, the input string. The durable fix validates and encodes server-side, every time.
Tools
PHPHTMLPurifierOWASP

Critical Literature Review

Built

Network Routing & Switching

The routing foundation underneath every network-security control: multi-protocol routing, redistribution and structured troubleshooting in Cisco Packet Tracer.

Routing protocols

Multi-Protocol Routing & Redistribution

Built
Built a multi-router topology running RIPv2 on one domain and OSPF (process 1, area 10) on another, with a border router performing RIP ↔ OSPF route redistribution so every host could reach every other.
Takeaway
Redistribution is where routing designs quietly break: metrics don't translate between protocols, so the boundary router has to be told how to value routes it didn't learn natively.
Tools
Cisco IOSRIPv2 / OSPFPacket Tracer
Troubleshooting

Fault-Finding a Broken Topology

Built
Worked a pre-broken network back to full connectivity, reasoning from symptoms (failed pings, missing routes) through the OSI layers to the misconfiguration, then verifying the fix end-to-end.
Takeaway
Methodical, layer-by-layer troubleshooting beats guessing, the same discipline a Quality investigation uses to find a root cause.
Tools
Cisco IOSshow / debug

Cloud Information Security

Cloud threat analysis paired with hands-on Azure build-out.

Threat analysis

Insufficient Identity, Credential, Access & Key Management

Built
A full threat analysis of one of the CSA Top Threats to Cloud Computing 2024: definition, organisational impacts (data breach, control-plane takeover, cryptojacking, broken key separation) and a layered remediation plan from MFA and least privilege to key vaults, KMS rotation and continuous monitoring.
